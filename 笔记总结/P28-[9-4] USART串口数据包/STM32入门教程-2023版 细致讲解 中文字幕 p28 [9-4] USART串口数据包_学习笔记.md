## 一、为什么需要数据包？

串口只能逐字节收发。当需要连续发送多字节数据（如陀螺仪 XYZ 三轴数据）时：

```
发送: X Y Z X Y Z X Y Z ...
            ↑
接收方可能从任意位置开始接收 → 数据错位
```

**数据包的作用**: 把同一批数据"打包"，通过包头/包尾分割，接收方知道哪个是 X、哪个是 Y、哪个是 Z。

## 二、两种数据包格式

### 2.1 本课程定义的数据包

| 类型 | 包头 | 格式 | 包尾 | 测试命令 |
|:---|:---|:---|:---|:---|
| **HEX 数据包** | `0xFF` | `FF + [4字节数据] + FE` | `0xFE` | `FF 66 88 AB CD FE` |
| **文本数据包** | `@` | `@ + 指令 + \r\n` | `\r\n` | `@LED_ON\r\n` |

### 2.2 HEX 数据包格式详解

```
┌────────┬──────────────────────┬────────┐
│ 包头   │      载荷 (Payload)   │ 包尾   │
│  0xFF  │   固定长度 N 字节     │  0xFE  │
└────────┴──────────────────────┴────────┘
```

- **固定包长**: 每个数据包载荷长度固定（如 4 字节），包头出现 → 收 N 个 → 等包尾
- **可变包长**: 载荷中有"长度"字段，包头出现 → 收长度 → 按长度收数据 → 等包尾

### 2.3 文本数据包格式详解

```
┌────────┬──────────────────────────┬────────┐
│ 包头   │       载荷 (Payload)      │ 包尾   │
│  @     │  任意文本（除 @ 和 \n）   │  \r\n  │
└────────┴──────────────────────────┴────────┘
```

- 载荷 = 字符串，直接包含有意义的英文字母/数字
- 解析后对字符串做 `strcmp()` 判断指令，无需关心 HEX 值
- 几乎不用担心载荷和包头包尾重复（`@` 和 `\n` 很容易避免）

## 三、HEX vs 文本数据包 对比

| 维度 | HEX 数据包 | 文本数据包 |
|:---|:---|:---|
| **数据形式** | 原始字节（0x00~0xFF） | 编码后的字符（ASCII/UTF-8） |
| **效率** | ⭐⭐⭐ 极高（发 100 只需 1 字节） | ⭐ 低（发 "100" 需 3 字节，还要转换） |
| **可读性** | ❌ 不可读，需对照协议 | ⭐⭐⭐ 直观，一眼看懂命令 |
| **灵活性** | ⚠️ 载荷可能和包头包尾冲突 | ⭐⭐⭐ 灵活，可变长度随意 |
| **解析难度** | ⭐⭐ 需要状态机 | ⭐ 字符串比对简单 |
| **典型场景** | 传感器数据（陀螺仪、温湿度） | AT 指令、G-code、人机交互 |

## 四、接收数据包的核心方法：状态机

### 4.1 状态转移图

```
              收到 0xFF                收到 N 个数据
    ┌─────────────────┐    ┌─────────┐    ┌──────────────┐
    │  S=0             │    │  S=1    │    │  S=2          │
    │  等待包头         │───→│  接收数据│───→│  等待包尾      │
    │                  │    │         │    │               │
    └─────────────────┘    └─────────┘    └──────────────┘
           ↑                                      │
           │         收到 0xFE（完成！）             │
           └──────────────────────────────────────┘
```

### 4.2 核心思路

- 每收到 1 个字节 → 进一次中断
- 在中断中用变量 `S` 记住当前"状态"
- 根据 `S` 值执行不同的处理逻辑，处理后决定是否转移到下一个状态

### 4.3 固定包长 HEX 数据包接收代码

```c
// ===== 全局变量 =====
uint8_t Serial_RxPacket[4];   // 接收到的数据（载荷）
uint8_t Serial_RxFlag;        // 接收完成标志

// ===== 接收状态机（放在 USART1_IRQHandler 中） =====
void USART1_IRQHandler(void)
{
    static uint8_t RxState = 0;   // 状态变量: 0=等包头, 1=收数据, 2=等包尾
    static uint8_t pRxData = 0;   // 当前接收到的字节数

    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)
    {
        uint8_t RxData = USART_ReceiveData(USART1);

        switch (RxState)
        {
        case 0:  // 等待包头 0xFF
            if (RxData == 0xFF)
            {
                RxState = 1;       // 包头正确 → 进入收数据状态
                pRxData = 0;       // 清零计数
            }
            break;

        case 1:  // 接收数据
            Serial_RxPacket[pRxData] = RxData;
            pRxData++;
            if (pRxData >= 4)      // 收满 4 字节数据
            {
                RxState = 2;       // → 进入等包尾状态
            }
            break;

        case 2:  // 等待包尾 0xFE
            if (RxData == 0xFE)
            {
                RxState = 0;       // 包尾正确 → 完成一包，回初始状态
                Serial_RxFlag = 1; // 置标志位通知主程序处理
            }
            break;
        }

        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}
```

### 4.4 可变包长文本数据包接收代码（简化版）

```c
// ===== 全局变量 =====
char Serial_RxString[100];    // 接收字符串缓冲区
uint8_t Serial_RxFlag;        // 接收完成标志

void USART1_IRQHandler(void)
{
    static uint8_t RxState = 0;   // 0=等包头(@), 1=收数据(等\n)
    static uint8_t pRx = 0;

    if (USART_GetITStatus(USART1, USART_IT_RXNE) == SET)
    {
        uint8_t RxData = USART_ReceiveData(USART1);

        if (RxState == 0)                        // 等待包头 @
        {
            if (RxData == '@')
            {
                RxState = 1;
                pRx = 0;
            }
        }
        else if (RxState == 1)                   // 接收数据，直到 \n
        {
            if (RxData == '\n')                  // 包尾 → 完成
            {
                RxState = 0;
                Serial_RxString[pRx] = '\0';    // 补字符串结束符
                Serial_RxFlag = 1;
            }
            else if (RxData != '\r')             // 正常字符 → 存入
            {
                Serial_RxString[pRx] = RxData;
                pRx++;
            }
        }

        USART_ClearITPendingBit(USART1, USART_IT_RXNE);
    }
}
```

## 五、主程序处理（发送 + 接收）

```c
// main.c

#include "stm32f10x.h"
#include "OLED.h"
#include "Serial.h"
#include "Key.h"
#include <string.h>

extern uint8_t Serial_RxPacket[4];
extern uint8_t Serial_RxFlag;

int main(void)
{
    OLED_Init();
    Serial_Init();
    Key_Init();

    uint8_t txData[6] = {0xFF, 0x01, 0x02, 0x03, 0x04, 0xFE};
    uint8_t counter = 0;

    while (1)
    {
        // ===== 发送数据包（按一下按键发一次） =====
        if (Key_GetNum() == 1)
        {
            txData[1] = counter >> 24;       // 高位
            txData[2] = counter >> 16;
            txData[3] = counter >> 8;
            txData[4] = counter;             // 低位
            counter++;

            Serial_SendArray(txData, 6);     // 发送整个数据包

            OLED_ShowHexNum(2, 1, txData[1], 2);
            OLED_ShowHexNum(2, 4, txData[2], 2);
            OLED_ShowHexNum(2, 7, txData[3], 2);
            OLED_ShowHexNum(2, 10, txData[4], 2);
        }

        // ===== 接收数据包（中断置标志后处理） =====
        if (Serial_RxFlag == 1)
        {
            OLED_ShowHexNum(4, 1, Serial_RxPacket[0], 2);
            OLED_ShowHexNum(4, 4, Serial_RxPacket[1], 2);
            OLED_ShowHexNum(4, 7, Serial_RxPacket[2], 2);
            OLED_ShowHexNum(4, 10, Serial_RxPacket[3], 2);

            Serial_RxFlag = 0;               // 清除标志
        }
    }
}
```

## 六、文本数据包指令解析示例

```c
// 主程序中处理接收到的文本指令
if (Serial_RxFlag == 1)
{
    // 打印接收内容
    OLED_ShowString(2, 1, Serial_RxString);

    // 指令判断
    if      (strcmp(Serial_RxString, "LED_ON")   == 0) { LED_ON();   Serial_SendString("LED_ON OK\r\n");  }
    else if (strcmp(Serial_RxString, "LED_OFF")  == 0) { LED_OFF();  Serial_SendString("LED_OFF OK\r\n"); }
    else if (strcmp(Serial_RxString, "BUZZER")   == 0) { BUZZER();   Serial_SendString("BUZZER OK\r\n");  }
    else                                                { Serial_SendString("ERROR COMMAND\r\n");        }

    Serial_RxFlag = 0;
}
```

## 七、设计数据包的关键问题

### 7.1 固定包长 vs 可变包长

| | 固定包长 | 可变包长 |
|:---|:---|:---|
| **优点** | 简单，收够 N 字节即可 | 灵活，适应不同数据长度 |
| **缺点** | 不够灵活，发短数据也占满 | 需要在载荷中传"长度"字段 |
| **适用** | 数据量始终固定的场景 | 数据长度多变的场景 |

### 7.2 载荷与包头包尾冲突问题

| 场景 | 解决方案 |
|:---|:---|
| 载荷不会和包头包尾重复 | 可变包长直接用 |
| HEX 包头=0xFF，载荷可能出现 0xFF | ① 用固定包长（不管内容）；② 转义字符（如 `0xFD` 开头转义） |
| 文本包（@ + 数据 + \n） | 载荷避开 @ 和 \n 即可，很容易做到 |

### 7.3 发送任意类型数据

```c
// 把任意类型数据转换为字节流发送
uint16_t data16 = 0x1234;
float    data32 = 3.14f;

// 方法：用 uint8_t* 指针指向目标数据的首地址
Serial_SendArray((uint8_t*)&data16, sizeof(data16));
Serial_SendArray((uint8_t*)&data32, sizeof(data32));
```

> 结构体也同样适用，因为内存中一切都是字节流。

## 八、知识总结

```
                       串口数据包设计

          ┌─────────────────┼─────────────────┐
          ▼                                    ▼
   ┌──────────────┐                    ┌──────────────┐
   │  HEX 数据包   │                    │ 文本数据包     │
   │ FF + 数据 + FE│                    │ @ + 指令 + \n │
   └──────┬───────┘                    └──────┬───────┘
          │                                    │
          ├─ 传感器原始数据                     ├─ 人机交互指令
          ├─ 效率高 (1字节=1个数)               ├─ 可读性强
          └─ 需防冲突                           └─ 灵活可变

             ┌────────────────────────┐
             │     接收方式：状态机    │
             ├────────────────────────┤
             │  S=0 → 等包头          │
             │  S=1 → 收数据/长度      │
             │  S=2 → 等包尾 → 完成！  │
             └────────────────────────┘
```

### 常见坑点

| 坑 | 原因 | 解决 |
|:---|:---|:---|
| 接收数据错位 | 从数据流中间开始接收 | 必须用包头同步，状态机从 S=0 开始 |
| 丢数据 | 状态机逻辑有 bug，状态转移错误 | 画状态转移图，对照流程图写代码 |
| 文本包收不到 | 没打换行符 | 发送时必须带 `\r\n` |
| HEX 包载荷含 0xFF 误判 | 可变包长 + 载荷含包头值 | 用固定包长或转义字符 |
| 接收完忘清标志 | `RxFlag` 未清零 | 主循环处理完立即 `= 0` |
