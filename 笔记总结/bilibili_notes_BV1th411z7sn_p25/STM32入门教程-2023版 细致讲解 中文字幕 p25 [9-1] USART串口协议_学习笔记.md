## 2. 本节程序现象预览

视频开头先展示后续会写的两个程序。

| 程序 | 视频中展示的功能 |
|---|---|
| 串口发送 | STM32 通过 USB 转串口模块，把数据发送到电脑串口助手显示 |
| 串口发送 + 接收 | 电脑串口助手发送数据给 STM32，STM32 接收后回传，并在 OLED 上显示 |

### 2.1 串口发送程序

视频中预览的发送函数包括：

```c
Serial_SendByte(0x41);        // 发送一个字节
Serial_SendArray(MyArray, 4); // 发送数组，例如 0x42、0x43、0x44、0x45
Serial_SendString(...);       // 发送字符串
Serial_SendNumber(...);       // 发送数字
```

还提到会给出三种实现 `printf` 的方法，把 C 语言常用的格式化打印函数移植到串口输出，用于向电脑串口助手打印消息。

### 2.2 HEX 模式与文本模式

视频用 `0x41` 演示串口助手显示方式：

| 发送数据 | 串口助手模式 | 显示结果 | 原因 |
|---|---|---|---|
| `0x41` | HEX 模式 | `41` | 直接显示字节值 |
| `0x41` | 文本模式 | `A` | 按 ASCII 表把 `0x41` 映射成字符 `A` |

视频中还说明：串口实际发送的是二进制数，也就是字节数据；如果想显示成字符，就需要数据到字符的映射表，最常用的是 ASCII 表。`0x41`、`0x42`、`0x43`、`0x44`、`0x45` 分别对应 `A`、`B`、`C`、`D`、`E`。

## 3. 为什么需要通信接口

视频中给出的核心解释是：通信的目的是将一个设备的数据传送到另一个设备，从而扩展硬件系统。

STM32 内部有很多功能模块，例如定时器计数、PWM 输出、AD 采集等。这些内部外设的寄存器和数据寄存器都在芯片内部，可以直接读写。

但很多功能 STM32 内部没有，例如：

| 外部功能 | 视频中的例子 |
|---|---|
| 无线控制 | 蓝牙无线遥控 |
| 姿态测量 | 陀螺仪、加速度计 |
| 外部数据读取 | 外挂芯片内部的数据 |

这些外挂芯片的数据在 STM32 外部，STM32 要获取或控制它们，就必须通过一根或多根通信线进行数据发送和接收。

## 4. 通信协议的作用

通信协议的作用是制定通信规则，通信双方按同一套规则收发数据。

视频用“考试传答案”的例子说明：双方可以约定先咳嗽一声代表开始，再用手势表示具体数据。这个约定就是一种通信协议。

在单片机通信中，协议需要约定的内容包括：

| 协议内容 | 串口中对应的问题 |
|---|---|
| 线怎么接 | `TX`、`RX`、`GND` 如何连接 |
| 0 和 1 怎么表示 | 高低电平或差分电压如何对应逻辑值 |
| 什么时候开始发送 | 起始位产生下降沿 |
| 每一位持续多久 | 由波特率决定 |
| 一个字节如何组织 | 起始位、数据位、校验位、停止位 |
| 如何发现错误 | 奇偶校验等 |

## 5. 常见通信接口与分类

视频中列出 STM32F103C8T6 支持的通信接口，包括 USART、I2C、SPI、CAN、USB。

| 接口 | 视频中提到的引脚/特征 |
|---|---|
| USART 串口 | `TX` 发送，`RX` 接收 |
| I2C | `SCL` 时钟，`SDA` 数据 |
| SPI | 出现于通信接口列表，后续章节学习 |
| CAN | 使用差分线，属于半双工理解范畴 |
| USB | 使用差分线，属于半双工理解范畴 |

### 5.1 全双工、半双工、单工

视频中按通信方向解释了三种方式：

| 类型 | 含义 | 视频中的说明 |
|---|---|---|
| 全双工 | 发送和接收可以同时进行 | 串口有 `TX` 和 `RX` 两根线，发送线和接收线互不影响 |
| 半双工 | 同一根数据线不能同时双向传输 | I2C、CAN、USB 这类只有一组数据通道的通信可按半双工理解 |
| 单工 | 数据只能从一个设备到另一个设备 | 只需要单向传输时，只接一根 `TX -> RX` 即可 |

## 6. 串口硬件连接

视频中说明，常见串口通信模块一般有四个引脚：

| 引脚 | 作用 |
|---|---|
| `VCC` | 供电 |
| `GND` | 公共参考地 |
| `TX` / `TXD` | 数据发送 |
| `RX` / `RXD` | 数据接收 |

串口连接时必须交叉连接：

```text
设备 1 TX  --->  设备 2 RX
设备 1 RX  <---  设备 2 TX
设备 1 GND ----  设备 2 GND
```

视频特别强调：`TX` 和 `RX` 是相对 `GND` 的单端信号，所以严格来说 `GND` 也属于通信连接的一部分。没有公共地，高低电平就没有统一参考。

当只需要单向通信时，可以只接一根通信线。例如设备 1 只向设备 2 发送数据，就只接设备 1 的 `TX` 到设备 2 的 `RX`。

## 7. 串口电平标准

视频中说明，电平标准规定“数据 1 和数据 0 用什么电压表示”。

| 电平标准 | 视频中给出的规则/特点 |
|---|---|
| TTL 电平 | 单片机电路最常见，高电平电压通常就是 `VCC` 电压；STM32 是 3.3V 器件 |
| RS232 电平 | `-3V ~ -15V` 表示 1，`+3V ~ +15V` 表示 0；电压范围大，常用于大型机器/干扰较强环境 |
| RS485 电平 | 用两线压差表示逻辑值，正压差和负压差分别表示 1/0；适合较强抗干扰场景 |

结论：电平标准不一致时，需要加电平转换芯片。STM32 直接输出的是 TTL/CMOS 类电平，不能直接和 RS232、RS485 电平硬接。

## 8. 串口软件协议：数据帧

串口在软件层面要把 0/1 组成一个完整的数据帧。视频中讲到的帧结构为：

```text
空闲状态 -> 起始位 -> 数据位 -> 可选校验位 -> 停止位 -> 空闲状态
```

| 字段 | 视频中的解释 |
|---|---|
| 空闲状态 | 不发送数据时，线路保持高电平 |
| 起始位 | 固定低电平，产生下降沿，告诉接收方“我要发送数据了” |
| 数据位 | 真正传输的数据，通常 8 位；串口低位先行 |
| 校验位 | 可选，用于一定程度的错误检测 |
| 停止位 | 固定高电平，让引脚回到空闲状态，表示一帧结束 |

### 8.1 起始位为什么需要下降沿

如果没有起始位，线路空闲时是高电平，而数据位也可能是高电平，接收方无法判断发送什么时候开始。

起始位固定为低电平，会从空闲高电平产生下降沿。接收端检测到下降沿后进入接收状态，并按约定波特率采样后续数据位。

### 8.2 停止位

视频中提到停止位可以配置为：

| 停止位长度 | 说明 |
|---|---|
| 1 位 | 常见配置，两个数据帧可以紧接发送 |
| 1.5 位 | 可选配置 |
| 2 位 | 数据帧之间高电平间隔更宽 |

停止位结束后，线路继续保持高电平，进入空闲状态，等待下一次起始位下降沿。

## 9. 波特率

波特率决定每一位持续多久。视频中实测例子：

| 波特率 | 每一位时间 | 视频中的现象 |
|---:|---:|---|
| `9600` | 约 `104 us` | 发送 `0x55` 时，每一位宽度约 100 多微秒 |
| `4800` | 约 `208 us` | 波特率变为一半，波形时间宽度变为原来的两倍 |

计算方式：

```text
9600 波特率：每位时间 = 1 / 9600 ≈ 104 us
4800 波特率：每位时间 = 1 / 4800 ≈ 208 us
```

如果一帧采用 1 个起始位、8 个数据位、1 个停止位、无校验，那么一帧共 10 位。

## 10. 奇偶校验

视频中重点讲了奇校验和偶校验。

| 校验方式 | 规则 |
|---|---|
| 奇校验 | 数据位 + 校验位中，`1` 的总数保持奇数 |
| 偶校验 | 数据位 + 校验位中，`1` 的总数保持偶数 |

### 10.1 奇校验例子

视频中举例：

| 数据 | 数据中 1 的个数 | 奇校验位 | 加校验位后的 1 的总数 |
|---|---:|---:|---:|
| `0000 1111` | 4，偶数 | 1 | 5，奇数 |
| `0000 1110` | 3，奇数 | 0 | 3，奇数 |

发送方补校验位，接收方收到后检查数据位加校验位中 `1` 的个数。如果奇偶特性不符合约定，就认为传输出错，可以丢弃或要求重传。

局限：如果有两位同时出错，奇偶性可能不变，就检测不出来。因此奇偶校验检出率不高。视频中提到，如果想要更高检出率，可以了解 CRC 校验，STM32 内部也有 CRC 外设。

## 11. 数据位与校验位的两种描述方式

视频中说明，数据位和校验位有两种描述习惯：

| 描述方式 | 含义 |
|---|---|
| 合并描述 | 9 位数据 = 8 位有效数据 + 1 位校验位 |
| 分开描述 | 数据位是有效载荷，校验位单独列出 |

串口助手软件中常见的是分开描述，例如“数据位 8 位、校验位无/奇/偶、停止位 1 位”。两种说法描述的是同一个数据帧结构。

## 12. 示波器实测波形

视频最后用示波器观察 `TX` 引脚波形。测量方式是：探头 `GND` 接负极，探头接发送设备的 `TX` 引脚，然后发送数据。

### 12.1 发送 `0x55`

参数：波特率 `9600`，8 位数据，1 位停止位，无校验。

```text
空闲：高电平
起始位：0
数据位：1 0 1 0 1 0 1 0   （0x55 低位先行）
停止位：1
```

每位时间约 `104 us`。在 STM32 中，这种根据字节数据自动翻转 `TX` 引脚电平的工作由 USART 外设完成。

### 12.2 软件模拟串口的思路

视频中提到，如果不用 USART 外设，也可以软件模拟：

| 方向 | 软件模拟方法 |
|---|---|
| 发送 | 定时器定时，例如每 `104 us` 调一次 GPIO 写引脚，按数据帧要求输出高低电平 |
| 接收 | 外部中断检测起始位下降沿，再按采样时钟定时读取 `RX` 引脚，最终拼成一个字节 |

但正常使用时，这些都由 USART 外设自动完成。

### 12.3 其他波形

| 发送数据/配置 | 视频中观察到的波形特点 |
|---|---|
| `0xAA` | 起始位后按低位先行发送 `0 1 0 1 0 1 0 1` |
| `0xFF` | 起始位后 8 个数据位都是高电平，然后停止位 |
| `0x00` | 起始位后 8 个数据位都是低电平，最后停止位回到高电平 |
| 波特率 `4800` | 波形变化趋势不变，但每位时间变成 `9600` 时的两倍 |
| `0x55` + 偶校验 | `0x55` 中 1 的个数已有 4 个，偶校验位为 0 |
| 2 位停止位 | 连续发送两个数据帧时，中间高电平停止位宽度更长 |

## 13. 本节总结

1. 通信的目的是在设备之间传送数据，让 STM32 能连接和控制外部模块。
2. 通信协议规定双方如何接线、如何表示 0/1、如何组织数据帧、如何检查错误。
3. USART 串口使用 `TX` 发送、`RX` 接收，双向通信时要交叉连接并共地。
4. STM32 常见串口电平是 3.3V TTL；如果连接 RS232 或 RS485，需要电平转换。
5. 串口空闲为高电平，一帧数据由起始位、数据位、可选校验位、停止位组成。
6. 波特率决定每位持续时间，双方必须一致，否则接收端采样会错位。
7. HEX 模式显示字节本身，文本模式会按 ASCII 表把字节解释成字符。
8. USART 外设会自动完成引脚电平翻转、数据帧封装和接收采样；软件只需要配置参数并读写数据。
