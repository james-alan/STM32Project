## 一、课程概览

上节课介绍了 MPU6050 的硬件结构和寄存器，本节课进入实战——通过软件模拟 I2C 时序（俗称 bit-banging）来读写 MPU6050。为什么用软件模拟而不直接用 STM32 的硬件 I2C？两个原因：一是软件 I2C 更容易理解和 debug，是所有 I2C 学习者的第一站；二是 MPU6050 的硬件 I2C 对时序要求比较苛刻，软件 I2C 虽然慢一些但胜在稳定可控。

> **提示**: 软件 I2C 的关键在于对时序的精确把控。程序中的每一步操作都必须严格遵守 I2C 协议的时序规则。写得对就是对的，写错一个地方整个通信都会挂。

## 二、硬件接线与 GPIO 初始化

### 2.1 接线表

| STM32 引脚 | 连接 | MPU6050 模块 | 说明 |
|:---:|:---:|:---|:---|
| `PB10` | → | `SCL` | I2C 时钟线（软件控制，任意 GPIO 均可） |
| `PB11` | ↔ | `SDA` | I2C 数据线（需在输入/输出间动态切换） |
| `3.3V` | → | `VCC` | 供电（模块板载 LDO） |
| `GND` | — | `GND` | 地线 |

> **关键**: I2C 要求 SCL 和 SDA 必须有上拉电阻（通常 4.7kΩ）。MPU6050 模块板上已自带，所以不需要外接。但如果你用的是裸芯片，别忘了加。

### 2.2 GPIO 配置要点

软件 I2C 不同于硬件 I2C——引脚就是普通的 GPIO，时钟和数据时序完全由软件代码手动控制。SDA 引脚需要在"输出"和"输入"之间频繁切换：

- **写数据时**：SDA 配置为推挽输出，可以主动拉低或置高
- **读数据时**：SDA 配置为浮空输入（或开漏上拉输入），释放控制权让从机操作

`SCL` 始终由主机控制，全程保持推挽输出即可。

## 三、软件 I2C 六个基本时序单元的实现

回顾 p31 学的六个基本单元：起始条件、停止条件、发送字节、接收字节、发送应答、接收应答。现在我们用 GPIO 操作逐个实现它们。

> **通用前提**: 以下代码假设已定义了底层操作函数 `SCL_W()`、`SCL_R()`、`SDA_W(x)`、`SDA_R()`，以及系统微秒延时。实际工程中通过宏或 inline 函数实现。

### 3.1 起始条件（Start Condition）

I2C 规定：SCL 高电平时，SDA 从高变低。程序实现分三步：

1. 确保 SDA 释放为高电平
2. 确保 SCL 释放为高电平
3. 拉低 SDA → 产生下降沿

```c
void MyI2C_Start(void)
{
    SDA_W(1);       // 先释放 SDA（确保是高电平起步）
    SCL_W(1);       // 释放 SCL
    SDA_W(0);       // SDA 从高拉低 → Start!
    SCL_W(0);       // 拉低 SCL，为后续传输做准备
}
```

> **注意**: 最后一步拉低 SCL 是为了"清理战场"，确保每个时序单元结束时 SCL 都处于低电平，方便下一个单元接着使用。除了停止条件外，所有单元都遵循这个惯例。

### 3.2 停止条件（Stop Condition）

I2C 规定：SCL 高电平时，SDA 从低变高。但因为开始时 SDA 不一定是低电平，所以需要先拉低 SDA 确保起点正确：

```c
void MyI2C_Stop(void)
{
    SDA_W(0);       // 先拉低 SDA（确保从低起步，以便后续产生上升沿）
    SCL_W(1);       // 释放 SCL 到高电平
    SDA_W(1);       // SDA 从低拉高 → Stop!
}
```

停止条件后，SCL 和 SDA 都回到高电平，总线进入空闲状态。

### 3.3 发送一个字节

核心思路：SCL 低电平时放数据，SCL 高电平时保持数据稳定（从机读取）。**I2C 是高位先行（MSB First）**，先发 bit7，后发 bit0。

```c
void MyI2C_SendByte(uint8_t Byte)
{
    uint8_t i;
    for (i = 0; i < 8; i++)
    {
        // 将当前最高位放在 SDA 上
        // 第一次循环: Byte & 0x80 → 取 bit7
        // 第二次循环: Byte & 0x40 → 取 bit6, 以此类推
        SDA_W(Byte & (0x80 >> i));

        SCL_W(1);   // 释放 SCL（高电平）→ 从机读取 SDA
        SCL_W(0);   // 拉低 SCL → 准备放下一位
    }
}
```

> **原理**: `Byte & (0x80 >> i)` 为什么能取到每一位？0x80 是二进制 `10000000`，右移 i 位后依次变成 `01000000`、`00100000`……与 Byte 按位相与，结果非零即一。而 `SDA_W()` 函数具有非零即一的特性，所以即使结果是 `0x80` 也会被当作高电平处理。

如果你对按位与不放心，也可以写成更直白的形式：

```c
if ((Byte & (0x80 >> i)) == 0)
    SDA_W(0);
else
    SDA_W(1);
```

两种写法在逻辑上等价，选你喜欢的方式。

### 3.4 接收一个字节

发送和接收是对称的：发送时主机放数据、从机读；接收时从机放数据、主机读。**主机在接收前必须释放 SDA**，否则会干扰从机放数据。

> 这个设计可以用"123木头人"游戏来理解：SCL 低电平 = "123"（可以动、可以放数据），SCL 高电平 = "木头人"（不许动、只能读数据）。起始/停止条件之所以"在 SCL 高电平时必须动 SDA"，正是因为它们需要打破这个规则，以此来和普通数据传输区分开——这种设计保证了起始/停止的唯一性和可识别性。

```c
uint8_t MyI2C_ReceiveByte(void)
{
    uint8_t i, Byte = 0;
    SDA_W(1);               // 释放 SDA（主机切换为输入模式）

    for (i = 0; i < 8; i++)
    {
        SCL_W(1);           // 释放 SCL → 从机放数据，主机读取

        if (SDA_R() == 1)   // 读 SDA 状态
            Byte |= (0x80 >> i);  // 对应的 bit 置 1

        SCL_W(0);           // 拉低 SCL → 从机准备下一 bit
    }
    return Byte;
}
```

`Byte |= (0x80 >> i)` 这句是接收的关键：初始 `Byte = 0x00`，每收到一个高电平的 bit（即 SDA 读到 1），就用按位或 `|` 把对应位置 1。因为 I2C 是高位先行，第一个收到的 bit 是 bit7，所以用 `0x80 >> i` 来对应。

### 3.5 发送应答（主机 → 从机）

时序等同于发送一位数据。

```c
void MyI2C_SendAck(uint8_t AckBit)
{
    SDA_W(AckBit);   // 0 = ACK, 1 = NACK
    SCL_W(1);
    SCL_W(0);
}
```

- 收到数据后回 `0`（ACK）：告诉从机"我收到了，继续"
- 不想再收数据时回 `1`（NACK）：告诉从机"够了，停"

### 3.6 接收应答（主机 ← 从机）

时序等同于接收一位数据。主机先释放 SDA，等 SCL 高电平期间读取从机是否拉低了 SDA。

```c
uint8_t MyI2C_ReceiveAck(void)
{
    uint8_t AckBit;
    SDA_W(1);               // 释放 SDA
    SCL_W(1);
    AckBit = SDA_R();       // 读从机应答: 0 = ACK, 1 = NACK
    SCL_W(0);
    return AckBit;
}
```

## 四、MPU6050 读写函数封装

有了六个基本单元，就可以封装出面向 MPU6050 的读写函数了。STM32 中常用的 MPU6050 驱动采用三层封装：

### 4.1 I2C 基本操作层

就是上面实现的六个函数：`MyI2C_Start`、`MyI2C_Stop`、`MyI2C_SendByte`、`MyI2C_ReceiveByte`、`MyI2C_SendAck`、`MyI2C_ReceiveAck`。它们是协议的最底层，和具体设备无关。

### 4.2 MPU6050 寄存器操作层

利用 I2C 基本操作，封装出"写一个寄存器"和"读一个寄存器"两个函数：

```c
#define MPU6050_ADDR  0xD0    // 从机地址 0x68 左移一位（含读写位）

/**
 * @brief  向 MPU6050 指定寄存器写入一个字节
 * @param  RegAddr  寄存器地址
 * @param  Data     要写的数据
 */
void MPU6050_WriteReg(uint8_t RegAddr, uint8_t Data)
{
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR);        // 从机地址 + 写 (bit0=0)
    MyI2C_ReceiveAck();
    MyI2C_SendByte(RegAddr);             // 寄存器地址
    MyI2C_ReceiveAck();
    MyI2C_SendByte(Data);                // 要写入的数据
    MyI2C_ReceiveAck();
    MyI2C_Stop();
}
```

> **注意**: `MPU6050_ADDR` 定义为 `0xD0`，这是 7 位地址 `0x68` 左移一位后的 8 位写法。因为库函数 `MyI2C_SendByte` 发送的是完整 8 位数据，最低位是读写位。`0xD0 = 11010000`，前 7 位 `1101000` 就是地址 0x68，最低位 0 是写。

读寄存器使用了 **Repeated Start**：

```c
/**
 * @brief  从 MPU6050 指定寄存器读一个字节
 * @param  RegAddr  寄存器地址
 * @return 读到的数据
 */
uint8_t MPU6050_ReadReg(uint8_t RegAddr)
{
    uint8_t Data;

    // 阶段一：告诉 MPU6050 要读哪个寄存器
    MyI2C_Start();
    MyI2C_SendByte(MPU6050_ADDR);        // 地址 + 写
    MyI2C_ReceiveAck();
    MyI2C_SendByte(RegAddr);             // 指定寄存器
    MyI2C_ReceiveAck();

    // 阶段二：切换到读，接收数据
    MyI2C_Start();                       // ← Repeated Start! 注意没有 Stop
    MyI2C_SendByte(MPU6050_ADDR | 0x01); // 地址 + 读 (bit0=1)
    MyI2C_ReceiveAck();
    Data = MyI2C_ReceiveByte();
    MyI2C_SendAck(1);                    // NACK → 主机说"读完了"
    MyI2C_Stop();

    return Data;
}
```

> **关键**: 读寄存器的第二个 `Start` 是 Repeated Start，两个 Start 之间没有 Stop！这意味着总线上数据帧是连贯的，总线锁不会被释放。这是 I2C 最经典的"指定寄存器再读"模式，所有的 I2C 从机都是这么设计的。

### 4.3 MPU6050 功能函数层

在寄存器读写的基础上，封装出业务级别的读数据函数：

```c
/**
 * @brief  MPU6050 初始化（唤醒芯片）
 */
void MPU6050_Init(void)
{
    MyI2C_Init();                           // 初始化 I2C 的 GPIO
    MPU6050_WriteReg(0x6B, 0x00);           // PWR_MGMT_1 = 0x00，唤醒芯片
    MPU6050_WriteReg(0x1A, 0x06);           // 配置低通滤波器
    MPU6050_WriteReg(0x19, 0x07);           // 设置采样率分频
}

/**
 * @brief  读取 MPU6050 的 ID（WHO_AM_I）
 * @return 应该返回 0x68，否则通信异常
 */
uint8_t MPU6050_GetID(void)
{
    return MPU6050_ReadReg(0x75);           // WHO_AM_I 寄存器
}

/**
 * @brief  读取加速度计 + 陀螺仪 + 温度（共 14 字节）
 * @param  AccX/Y/Z  输出，加速度计三轴数据（int16_t*）
 * @param  GyroX/Y/Z 输出，陀螺仪三轴数据（int16_t*）
 * @param  Temp      输出，原始温度数据
 */
void MPU6050_GetData(int16_t *AccX, int16_t *AccY, int16_t *AccZ,
                     int16_t *GyroX, int16_t *GyroY, int16_t *GyroZ)
{
    uint8_t DataH, DataL;

    // 加速度计 X 轴：0x3B(H) + 0x3C(L)
    DataH = MPU6050_ReadReg(0x3B);
    DataL = MPU6050_ReadReg(0x3C);
    *AccX = (DataH << 8) | DataL;           // 拼接 16 位有符号数据

    // 加速度计 Y 轴
    DataH = MPU6050_ReadReg(0x3D);
    DataL = MPU6050_ReadReg(0x3E);
    *AccY = (DataH << 8) | DataL;

    // 加速度计 Z 轴
    DataH = MPU6050_ReadReg(0x3F);
    DataL = MPU6050_ReadReg(0x40);
    *AccZ = (DataH << 8) | DataL;

    // 陀螺仪 X 轴：0x43(H) + 0x44(L)
    DataH = MPU6050_ReadReg(0x43);
    DataL = MPU6050_ReadReg(0x44);
    *GyroX = (DataH << 8) | DataL;

    // 陀螺仪 Y 轴
    DataH = MPU6050_ReadReg(0x45);
    DataL = MPU6050_ReadReg(0x46);
    *GyroY = (DataH << 8) | DataL;

    // 陀螺仪 Z 轴
    DataH = MPU6050_ReadReg(0x47);
    DataL = MPU6050_ReadReg(0x48);
    *GyroZ = (DataH << 8) | DataL;
}
```

## 五、主程序与 OLED 显示

```c
// main.c

#include "stm32f10x.h"
#include "OLED.h"
#include "MPU6050.h"

int main(void)
{
    OLED_Init();
    MPU6050_Init();

    // 验证通信
    uint8_t ID = MPU6050_GetID();
    OLED_ShowHexNum(1, 1, ID, 2);       // 应显示 68

    int16_t AX, AY, AZ, GX, GY, GZ;

    while (1)
    {
        MPU6050_GetData(&AX, &AY, &AZ, &GX, &GY, &GZ);

        OLED_ShowSignedNum(2, 1, AX, 5);
        OLED_ShowSignedNum(3, 1, AY, 5);
        OLED_ShowSignedNum(4, 1, AZ, 5);
    }
}
```

> **验证步骤**: 下载后先看 OLED 第一行是否显示 `68`——如果 WHO_AM_I 读到了 0x68，说明 I2C 通信正常。然后晃动模块，观察加速度计数据是否跟着变化。

## 六、常见问题与避坑

| 现象 | 原因 | 解决方法 |
|:---|:---|:---|
| WHO_AM_I 读不到 0x68 | I2C 通信根本没通 | 检查接线（SCL/SDA 没接反）、模块供电是否正常（LED 亮？）、代码中地址是否正确（0xD0） |
| 数据全为零 | 芯片在睡眠模式 | 确保 `MPU6050_Init()` 中写了 `0x6B = 0x00` 唤醒 |
| 数据读回来跳动但值不对 | 没拼对高低字节，或读取顺序错误 | 确认 H/L 寄存器的匹配关系（如 0x3B+0x3C 拼 X 轴加速度） |
| `ReceiveAck` 一直返回 NACK | 从机地址错误 | 用逻辑分析仪抓波形确认发送的地址字节，查数据手册核对 7 位地址 |
| 写着写着突然不动了 | 某一个 ACK 没收回来卡死 | 可以给 ACK 等待加超时机制，超过一定次数就报错返回 |
| 时序不对导致偶尔出错 | 软件延时不准确、中断打断 I2C 时序 | 使用精确的微秒延时函数，或在关键时序段关中断（`__disable_irq()`） |

其中"芯片未唤醒"是最常见的新手坑。MPU6050 上电后默认处于睡眠模式，所有传感器都不工作。上层代码可能看起来什么都没错，但你读上来的数据永远是零——因为传感器根本没启动。务必在初始化第一步就写 `PWR_MGMT_1 = 0x00`。

## 七、软件 I2C vs 硬件 I2C

本课使用的是软件模拟 I2C（bit-banging），下一课会讲解如何用 STM32 的硬件 I2C 外设。两者的对比：

| 特性 | 软件 I2C | 硬件 I2C |
|:---|:---|:---|
| 原理 | CPU 手动拉高/拉低 GPIO，模拟时序 | STM32 内部硬件自动产生时序 |
| 占用 CPU | 高（收发期间 CPU 一直在忙） | 低（DMA + 中断，CPU 可干别的事） |
| 速度 | 慢（受延时间和 CPU 速度限制） | 快（可达 400kHz+） |
| 灵活性 | 极高（任意 GPIO 都可，时序完全可控） | 低（只能绑固定引脚，时序由硬件决定） |
| 调试难度 | 低（代码就是时序，逻辑分析仪对照看即可） | 高（出问题往往是配置寄存器没写对） |
| 适用场景 | 学习、快速原型、任意 I/O 口通信 | 产品级、高速通信、省 CPU 带宽 |

> **提示**: 学会了软件 I2C，再看硬件 I2C 就简单了——硬件 I2C 本质上就是把软件模拟的逻辑变成了硬件自动执行，你需要做的只是配置好寄存器参数，告诉硬件"我要发一包数据"，硬件就会自动帮你跑完所有时序。

    ├─────────────────┤     ├──────────────────┤     ├─────────────────┤
